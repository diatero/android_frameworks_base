# 息屏小部件 UI 与功能优化分析

日期：2026-10-04。依据当前 SystemUI 实现和连接的 Mi 10 / umi。

## 2026-10-04 四套独立显示布局

新增“屏幕布局”，独立编辑息屏竖屏、息屏横屏、锁屏竖屏和锁屏横屏。
支持时间、独立日期/天气、通知、小部件、电量提示的拖动、缩放、百分比微调和显示开关；
每套布局可启用或恢复系统默认，草稿统一保存、返回放弃，旋转保留。
屏幕方向提供跟随系统、固定竖屏、固定横屏及自动旋转。
按用户反馈移除了底部解锁/指纹预留：新布局和原有小部件位置编辑器都可以放到屏幕底部，
预览不再显示预留区标记；四套布局保持独立。实际防烧屏位移受屏幕边界约束，避免底边内容被推到屏幕外。
最终编译成功，仅替换 SystemUI；12 项布局测试通过，实机四种显示状态确认可达底边，
检查用的临时布局/方向设置已恢复，SystemUI 崩溃缓冲区为空。
实现与验证记录见 [独立显示布局](aod-display-layouts.md)。

## 2026-10-04 可调显示效果与应用识别

- 新增“息屏显示效果”：亮度 5–100%、色彩饱和度 0–100%、标准/高清，以及低亮灰度、均衡、原色明亮三种预设。
- 亮度 100% 去除宿主的额外压暗；屏幕实际亮度仍由系统息屏策略控制。色彩变换保留透明度和纯黑背景。
- 高清使用全分辨率快照，标准保留半分辨率；烧屏位移、分钟刷新与内容更新合并继续生效。
- 原组件色彩/亮度预览、保存、返回放弃、恢复默认及旋转时的草稿保留均在独立的原生设置页面中提供。
- 选择列表显示应用图标、小部件名称与应用名称，按应用和小部件名称排序；管理页也显示选中组件所属应用。
- `JOBS=6 bash tools/build-umi.sh` 编译成功（16:21），仅暂存更新 SystemUI 并重启；用户随后手动验证无问题。
- 保留用户当前选择及显示效果设置，不恢复较早的组件或参数；验证期间用户可能继续调整。
- 下方 2026-10-03 的分析与验证属于历史记录，固定灰度/亮度及仅名称选择器的描述已由本次功能取代。

## 本次调整

- 管理页和布局编辑页使用 `#000000` 页面背景，标题栏、折叠遮罩、列表与预览外框同步改黑。
- 页面独立使用深色资源，系统切换为浅色时仍保持浅色文字和可辨识的开关、滑杆；不改变其他 SystemUI 页面的主题。
- 布局示意图使用黑色画布、白色时钟、灰色安全区域与指纹占位、带主题色描边的小部件位置框。
- 设置项保留原生深色卡片与系统强调色，用于区分可操作区域。

第三方小部件自己的背景属于其 RemoteViews 内容。本次改的是管理页面与预览环境，
没有删除第三方背景或修改真实锁屏小部件的内容。实际 AOD 仍使用现有灰度、35% 亮度快照。
因此，第三方绘制的大块灰色背景仍可能出现在预览与 AOD 中。

## 建议优先级

| 优先级 | 方向 | 当前问题与建议 | 验收重点 |
| --- | --- | --- | --- |
| P1 | 真实息屏预览（视觉） | 管理页目前显示原色 RemoteViews，实际 AOD 使用灰度和 35% 亮度。增加“锁屏 / 息屏”预览切换，复用实际快照渲染规则。 | 同一组件在预览和真实 AOD 的灰度、尺寸、裁切一致；预览按钮仍不可触发操作。 |
| P1 | 第三方背景适配（视觉） | 大块不透明背景在 AOD 上仍发灰。优先支持提供方的透明主题、息屏主题或专用精简组件；通用兼容模式需可回退，不宜按像素亮度直接把灰色删掉。 | 浅色卡片、深色卡片、图片及文字都不丢内容；锁屏保留提供方原始显示；逐个提供方验证。 |
| P1 | 可见状态与原因（功能） | 主开关不等于当前一定显示：AOD 未启用、未选组件、锁定内容权限未开放、提供方失效都会影响结果。增加状态说明及进入相关设置的入口。 | 用户能理解为什么不显示；临时接近传感器暂停或认证过渡不会被误报为永久错误。 |
| P1 | 尺寸适配（功能） | 当前以统一的 120–600 × 64–320 dp 范围为主，没有按提供方最小尺寸及缩放能力设置编辑范围。结合 `minWidth/minHeight/minResizeWidth/minResizeHeight/resizeMode` 给出推荐尺寸和裁切提示。 | 时钟、日程、音乐和工具组件在推荐尺寸下不截字；横屏空间不足时明确说明实际显示尺寸。 |
| P2 | 布局编辑反馈（视觉与功能） | 目前是占位框，未显示真实内容；安全区由通用时钟区域与底部指纹占位估算。提供真实内容预览、居中吸附、对齐参考线与实际指纹避让区域。 | 自定义时钟、通知、指纹目标和横屏下不重叠；吸附可通过滑杆细调。 |
| P2 | 选择与重新配置（功能） | 当前提供方选择器只有名称列表，易出现同名项；已有组件缺少直接重新配置入口。增加应用图标、应用名称、搜索及“配置”操作。 | 能区分同名组件；取消重新配置保留原组件，避免额外泄漏 AppWidget ID。 |
| P2 | 分别控制锁屏与息屏（功能） | 当前一个开关同时控制两处显示，布局也共用。提供“仅锁屏 / 仅息屏 / 两者”选项，后续按需要支持两套布局；锁定内容授权仍统一约束两处。 | 只启用一种模式时另一处不出现；转换过程不闪烁、不绕过隐私授权。 |
| P2 | 可读性与清晰度（视觉） | 实际 AOD 当前统一减至 35% 亮度并以半分辨率截图，细字、细线及深色原稿可能难辨。增加受限亮度档位，并测量小字是否需要按尺寸选择快照分辨率。 | 暗室和亮环境均可辨认；先测内存、渲染耗时和设备功耗，不直接宣称省电。 |
| P2 | 保存与退出（功能） | 现有“保存 / 返回放弃”行为明确，但未保存编辑退出没有提醒，主页面也没有恢复上次布局入口。按脏状态启用保存，并在有改动时提供保留或放弃的明确选择。 | 无改动返回不打扰；旋转、主题变化和进程恢复后草稿不意外写入正式设置。 |

## 已有能力与边界

当前已具备：烧屏位移、灰度低亮度快照、分钟刷新及内容更新合并、独立小部件宿主、
选择取消保留旧实例、布局草稿跨旋转保留、锁定内容授权、活动启动解锁流程，以及有限次数故障重试。
这些应继续作为回归验证项，不应被当成尚未实现的功能。

AOD 当前只展示快照，点击需先唤醒，再在真实锁屏组件上操作。无需为此次视觉调整改变这条交互规则。
列表类组件的离屏渲染及自动翻页兼容性仍取决于提供方，暂不宜承诺所有桌面组件都完整支持。

建议下一轮先完成“真实息屏预览、状态说明、提供方尺寸适配”，收益清晰且可独立验收；
第三方背景替换和亮度调节需在真实设备上分别验证兼容性与功耗。

## 实现依据

- `AodWidgetSettingsActivity.createPreview()`：原色真实组件预览及点击屏蔽。
- `AodWidgetSettingsActivity.chooseProvider()`：名称列表选择；`previewLayout()` 使用底部通用占位。
- `AodWidgetLayoutFragment` / `AodWidgetGeometry`：固定尺寸范围、草稿、滑杆与共享安全区域。
- `AodWidgetSection.addViews()` / `renderSnapshot()`：灰度、35% 亮度、半分辨率与现有 AOD 交互边界。
- `AodWidgetSection.desiredSurface()`：所有者、锁定状态、授权、遮挡与认证状态决定显示资格。
